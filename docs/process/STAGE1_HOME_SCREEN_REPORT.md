# Stage 1 — доработка стартовой страницы Buyer MVP

> Терминологическое уточнение: в этом отчёте описана React-страница `/`
> (`buyer_mvp/screens/HomeScreen.tsx`). Это не «Главный экран» Customer UI
> из ТЗ-001/ТЗ-023, где главным рабочим пространством являются карта и
> Bottom Sheet. Совпадение названий в прежней версии отчёта было причиной
> архитектурной неоднозначности.

## Классификация

L1: изменяется существующая React-страница и её визуальное поведение. Доменная модель, Repository Contract и Runtime Platform Core не изменяются.

## Context Report

1. Необходимо превратить технический список категорий на `/` в полноценную стартовую страницу Buyer MVP Stage 1.
2. Уже существуют загрузка `ProductGroup`, поиск, переходы в каталог, состояния loading/error и токены дизайн-системы.
3. Связанные материалы: контракт Buyer MVP (`src/buyer_mvp/types.ts`), существующий Catalog API, React Router и документация дизайн-системы. ТЗ-001/ТЗ-023 описывают другой, map-based интерфейс и не являются критериями приёмки этой страницы.
4. Риски: недоступность API, длинные названия категорий, узкие экраны, выход за границы Stage 1.
5. Открытые вопросы: реальные изображения категорий и редакционные тексты не определены. В Stage 1 использованы нейтральные локальные иллюстрации без нового API.

## Task Decomposition Report

### Уже реализовано

- API категорий и поиск;
- переходы в каталог по запросу и категории;
- базовые loading/error-состояния;
- дизайн-токены и адаптивный layout.

### Реализовано частично

- навигация существовала, но не формировала ясную структуру продукта;
- категории отображались плоскими служебными кнопками;
- стартовая страница не объясняла ценность сервиса.

### Отсутствовало

- визуальная иерархия стартовой страницы;
- быстрый обзор корневых категорий;
- адаптивная карточная сетка;
- продуктовые преимущества и выразительный поиск.

### Дефекты

- в пользовательских строках навигации присутствовала mojibake-кодировка;
- на мобильных устройствах длинный вертикальный список требовал избыточной прокрутки;
- CTA и основные сценарии имели одинаковый визуальный вес.

### Ограничения Stage 1

- без корзины, оплаты, рекомендаций, акций, отзывов и расширенных фильтров;
- без изменений Domain Models, Repository Contract и Platform Core;
- данные категорий по-прежнему поступают только через существующий Catalog API.

### Итоговый backlog

- HOME-001 (P0): собрать hero и поисковый сценарий;
- HOME-002 (P0): представить корневые категории адаптивной сеткой;
- HOME-003 (P1): обновить верхнюю навигацию и исправить пользовательские строки;
- HOME-004 (P1): сохранить loading/error и доступную клавиатурную семантику;
- HOME-005 (P1): проверить build и экран в браузере.

## Критерии приёмки

- поиск ведёт в `/catalog` с параметром `search`;
- карточка категории ведёт в `/catalog?group_id=...`;
- данные категорий не дублируются локальной моделью;
- loading/error остаются доступны пользователю;
- desktop и mobile не имеют горизонтального переполнения;
- проект проходит production build.

## Knowledge Delta

Стартовая страница Buyer MVP может быть существенно улучшена внутри React UI-слоя без расширения Stage 1: существующего `ProductGroup` достаточно для навигационных карточек, а редакционный визуальный слой может оставаться локальным и не входить в доменную модель. Наличие Runtime Platform Core в App Shell не означает, что локальное представление этой страницы должно получать отдельную доменную модель или новый Action-контракт.

## Self Review

- Scope: реализованы только HOME-001…HOME-005, новые продуктовые возможности не добавлялись.
- Architecture: изменения ограничены React-представлением и CSS; API и Platform Core не затронуты.
- UX: поиск и выбор категории сохранили прежние URL-контракты; добавлены адаптивные состояния desktop/mobile.
- Accessibility: сохранены семантические `main`, `section`, `nav`, `button`, `form`, подписи и заголовочная иерархия.
- Verification: `npm run build` и `npm run lint` проходят без ошибок; `git diff --check` не выявил whitespace-дефектов.
- Production smoke-test: собранный `dist` запущен локально и отвечает `HTTP 200 text/html`.
- API smoke-test: `/groups` отвечает корректно; каталог возвращает 9 товаров; поиск «молоко» возвращает 1 товар.
